Monocular height estimation · single nadir image · no stereo, no LiDAR

Metric elevation
from one image.

A pretrained depth model tells you which roof is higher. It cannot tell you how many metres. Chhaya (छाया, “shadow”) turns that relative surface into metres by solving a spatially varying calibration against a graph of physical anchors — public DEM samples, cast-shadow trigonometry, water flatness, survey points — each admitted only where it is actually valid.

What it measures

Every number on this page is produced by python -m unnat.cli study and read live from results/study.json. Nothing is typed in by hand. Re-run the study on your own machine and this page renders your numbers instead.

Accuracy against ground truth

Predicted DSM vs the exact surface that generated the image, averaged over independent scenes. Two baselines: a single global a·D + b fit, which is what you get without the anchor graph, and the public DEM on its own — the floor any monocular method has to clear before it is worth running at all.

Where it fails

Mean absolute error by land-cover class. Terrain is close to solved; buildings and canopy carry the error.

Is σ honest?

An uncertainty field is only worth showing if it predicts the error. For a Gaussian, 68% of pixels should fall inside 1σ.

Ablation — which parts earn their place

One depth inference per scene; every variant re-solves only the calibration. Each row therefore sees the identical depth field, so the difference between rows is the ablated component and nothing else.

The shadow physics window

Height from shadow length, h = L·tan(elevation), with no depth model involved. Sun too low and shadows sprawl across terrain; too high and they vanish under the resolution.

One free parameter

The calibration's smoothness weight. If accuracy were sharply peaked, this would be a knob you tune per scene rather than a method.

Throughput

Measured on the machine named below. Warm-up is timed separately and excluded; an out-of-memory result is recorded rather than hidden.

How it works

The problem with scaling depth

A monocular depth model returns an ordering, not a measurement. The usual fix is to fit one scale and one offset for the whole tile, H = a·D + b. That forces every anchor source to agree on two numbers, so the fit inherits the worst error of each: a 30 m public DEM is a fair description of bare earth and meaningless on a rooftop; a cast shadow measures height above local ground and says nothing about the datum.

Anchor-Graph Metric Calibration

Chhaya replaces the two scalars with two smooth fields solved on a coarse lattice, H(x,y) = a(x,y)·D(x,y) + b(x,y), minimising a robust data term over a heterogeneous anchor set plus a graph-Laplacian smoothness term. Anchors are typed: an absolute anchor states an elevation, a relative anchor states a difference between two pixels. Shadow measurements are always relative — reading one as an elevation is how a good height anchor silently becomes a bad datum anchor.

Degrade, don't fail

Three tiers, selected automatically from what the image actually carries. The tier in use is reported with its reason, so a planner knows how much to trust the output instead of guessing.

The calibration ladder

Tier A

Automatic (DEM)

Needs a CRS and a public DEM

DEM samples admitted only where segmentation says bare ground, road or water, plus shadow heights. Good terrain; absolute building height is weaker.

Tier B

GCP-assisted

Needs ≥3 points of known elevation

Everything Tier A has, plus survey points at full weight. Best available: the GCPs pin the datum that a DEM can only approximate.

Tier C

Physics only

Needs nothing but the image

Shadow trigonometry and an assumed ground plane. Relative structure is trustworthy; the datum is arbitrary and the interface says so.

Run it on your own image

The pipeline is a Python package with a CLI. It needs no data to demonstrate itself — it can generate a synthetic town with an exact known DSM — and it takes your GeoTIFF, PNG or JPG when you have one.

Open the notebook, set Runtime → Change runtime type → GPU, run all. It installs the deps, generates ground-truth test data, runs the pipeline and renders the outputs.

What these numbers are not

Being specific about this is more useful than a bigger headline figure.

  • The scenes are synthetic. They are rendered from a known DSM with ray-marched shadows and correct geospatial metadata, which makes ground truth exact and the plumbing genuinely testable. They are not satellite imagery, and a monocular model's behaviour on real sensor data is a separate question.
  • The DEM is simulated. --dem sim: degrades the true terrain to a 30 m posting with correlated noise at Copernicus GLO-30's stated accuracy. It is a development harness. Network DEM fetching is deliberately not wired up so that a run can never silently proceed with a DEM it failed to load.
  • Segmentation is heuristic. Colour and texture rules, not a trained model. It gates which DEM samples are admissible, so a better segmenter should improve Tier A directly — the interface takes a raster from any source.
  • Buildings dominate the error. Rooftop height is where a monocular method is weakest and where the anchor sources are sparsest: the DEM says nothing there by construction, and shadow anchors only survive for buildings isolated enough to cast a clean shadow.
  • A depth prior fought us. Depth Anything V2 applies a ground-level perspective prior to nadir imagery — on our benchmark its output correlated 0.69 with the image row index while the true surface correlated −0.15. The spatially varying calibration absorbs most of it, which is a large part of why AGMC beats the global fit so decisively here. That gap measures how badly a single scale fits a contaminated depth field, not how much the depth field knows.
  • It once built the city upside down. Because the terrain anchors outnumber the shadow anchors roughly sixty to one, an unconstrained fit found it cheaper to invert the depth field than to fight the perspective ramp: the scale field came out negative at every lattice node and buildings were rendered 2.6 m below the ground they stand on — while the headline error improved. No aggregate metric catches an inverted city. The scale field is now constrained positive, which is the pipeline's own documented convention rather than a new assumption, and a regression test reproduces the trap.

The open question

The floor column above is the one that decides whether any of this is worth running. When the reconstruction only matches the public DEM it was anchored to, the anchor graph is doing the work and the depth model is close to a passenger — good terrain, and structures it cannot yet place. The prototype fix that follows from that evidence is the decomposition the design has always called for: take the terrain from the DEM, take only the high-frequency object component from the depth model, and calibrate that component against the shadow anchors, which are the one source that actually measures height above ground. That is the next piece of work, and it is not done.
